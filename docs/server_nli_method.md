# 服务器上的通用 NLI 方法

本方法不训练模型权重。把 evidence 作为前提 E，把 claim 作为假设 C，让 Qwen-27B 判断逻辑蕴含关系，再确定性映射回事实核查标签。当前服务器模型 ID 为 `qwen38-27b`；调用明确设置 `enable_thinking=false`，使用温度 0、seed 42 和结构化 JSON。

## 逻辑定义

| 判断 | 含义 | 输出标签 |
|---|---|---|
| E ⊨ C | 满足证据的所有情况中，命题都成立 | SUPPORTS |
| E ⊨ ¬C | 满足证据的所有情况中，整个命题都不成立 | REFUTES |
| 两者均不能推出 | 现有证据不能确定命题真伪 | NOT ENOUGH INFO |

证据是当前可用的全部信息，但不是对整个世界的完整描述。提示词只给出这些宏观定义，没有具体机制、题目关键词或个别错误类型的提示。模型只接收 claim/evidence，不接收标签、组号、机制名或其他管理字段。

这与“双世界”思路的联系是：在 E 自身可满足的前提下，E ⊨ C 等价于 E ∧ ¬C 不可满足；E ⊨ ¬C 等价于 E ∧ C 不可满足。两个合取都可满足时，证据没有排除真、假任一可能，即 NEI。这里应检查合取式的**可满足性**，而不是某个世界里 E ∨ C 的真假：一旦 E 为真，E ∨ C 和 E ∨ ¬C 都为真，不能用它们区分标签。若 E 本身矛盾，经典逻辑会同时推出两边，三分类还需要额外约定；当前 NLI 不是一个形式逻辑证明器。

## 实际推理

每道题单次调用，返回一个简短 justification 和 relation。映射 ENTAILMENT → SUPPORTS、CONTRADICTION → REFUTES、NEUTRAL → NOT ENOUGH INFO。没有多数投票或逐题人工改答案。模型输出不满足固定 schema、被截断或无有效标签时，记录 INVALID 并计错，不重新抽答案。

英文通用指令的确切内容在 `prompts/v7/nli_system.txt`；完整服务器请求由 `src/ab_factcheck/server_search_v11.py` 的 `request('nli', claim=..., evidence=...)` 构造。NLI 输出上限 512 tokens，基线原协议上限 1024；结果成本使用实际 usage，而不是把上限当消耗。Schema 保留 justification、relation 的字段顺序，但实验没有证明字段顺序本身导致提升。

简短说明是非思考模式下的公开输出字段；请求未开启模型思考模式，接收端另检查 reasoning 字段和 reasoning token 计数。

原 A27 基线也要求只看证据，并给出了蕴含/矛盾/信息不足的定义。因此这里的收益应归于经过比较的整套 NLI 表述与输出协议；不能声称只有新方法才使用逻辑，也不能把观察到的提升归因于某一句提示词。尚未完成这种逐因素因果消融。

## 已尝试的替代方向

在相同开发筛选流程下比较过正反命题一致性、候选关系核验、语义规范化、三标签选项顺序平均、正负命题概率融合、多路投票、双蕴含二元阈值和中文通用指令。逻辑分解正确，并不保证模型能可靠判断每个分支；多调用也不自动提高准确率。各轮失败或未通过检验的结果均保留。

二元阈值方案分别获得 E ⊨ C 和 E ⊨ ¬C 的 A/B token 选择概率，用两个分支共享的阈值映射三分类。这不是模型正确率的校准概率。V13 的旧开发题初筛没有超过单次 NLI；最终结果以其冻结评估及审计为准。

V14 进一步比较直接询问整个命题是否必假，以及先给简短依据再作两次 YES/NO 判断。后者在旧开发初筛达到基础 21/21、挑战 18/21，既有 NLI 为 21/21、17/21；没有达到事前挑战至少多对 2 题的扩展门槛，按规则停止。这个小样本的 1 题优势不能说成已验证更好的方法。

## 证据边界与复现

V11、V12 对选定 NLI 使用此前未用于选方法的完整开发组，分别与服务器同期 A27 比较，均得到正向准确率变化，但没有通过各自事前分配的显著性门槛。

V13 已完成并通过独立脚本复算：基础 109/120 → 116/120（+5.83 pp）；挑战 134/236 → 161/236（+11.44 pp）。挑战单侧组置换 p=0.00001239776611328125，通过事前 alpha=0.00625；其他指标幅度限制也通过。挑战修正 31 题、损害 4 题，基础修正 9 题、损害 2 题。基础 NEI 召回下降 2.17 pp、挑战 REFUTES 召回下降 2.78 pp；不能说每个指标均上升。确认中 NLI 有 3 个无效输出，仍按错误计入分母。单次 NLI 的实际推理 token 为同期基线约 1.085 倍。

最终结论须同时阅读各轮 `RESULTS.md`、`assessment.json` 与 `audit.json`。开发结果不等于测试集结果；测试集未读取。V13 剩余确认挑战组只含六种机制，没有 SETCLOSE，不能据此单独声称新确认覆盖全部七机制。
