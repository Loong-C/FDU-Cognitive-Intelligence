# 无特殊提示词的微调路线：可行性评估

评估日期：2026-10-30。已阅读当前 NLI 分支、PJ 分支归档说明、任务要求、数据划分、V11–V15 结果及评测代码；只分析两份 `dev.jsonl`，并通过 SSH 只读检查服务器。此次未读取测试集样本、下载权重、安装依赖或启动训练。以下是实验建议，不是已取得的微调效果。

## 结论与建议

**值得开辟第三条路线：监督微调，让模型直接输出 SUPPORTS / REFUTES / NOT ENOUGH INFO。技术上可行，但尚不能保证优于现有 27B + NLI。**

建议主线采用可训练原始权重的 **Qwen3-8B + BF16 LoRA + 标签监督**，固定一句通用任务说明，训练与推理使用同一输入格式，不附加题型规则、示例、思维链或机制名称。若要求连自然语言任务说明也没有，则采用 **DeBERTa-v3-base + 三分类头**，直接输入 evidence / claim 文本对。

选择 8B 是为了先验证训练收益和昇腾训练链路，不代表它的能力已经超过 27B。比较时必须同时保留同一 8B、同一简短输入格式的微调前基线，区分“训练效果”和“更换模型效果”。建议正式实现时使用独立分支 `codex/finetune-label-only`；本次仅新增评估文档，未切换现有工作树。

## 仓库目前解决了什么

任务是基于英文证据判断陈述的三分类事实核查；课题允许训练开源模型，要求训练部署模型小于 30B。

| 路线 | 主要做法 | 现有证据与限制 |
| --- | --- | --- |
| `codex/nli` | 探索过双世界、JSON 约束、Z3、反命题一致性等；目前采用单次通用 NLI | 没有更新权重。V13 独立开发确认：基础 109/120 → 116/120，挑战 134/236 → 161/236；不是最终测试结果 |
| `codex/import-pj-materials-20261029` | 提高反驳门槛、加入细化规则的提示词 | 历史全量挑战准确率约 85%，但全量数据参与过优化，包含本仓库测试划分；不能直接与 NLI 的不同评测子集比较 |
| V15 统一受控比较 | 相同模型、输出结构与生成参数比较 NLI / PJ v3 | 挑战 148/168 对 156/168，未通过原定优越性标准；两种方法的错误均在 NEI；题目来自有限手写模板 |

来源：[方法说明](server_nli_method.md)、[跨轮结果](../experiments/server_summary/RESULTS.md)、[分支口径](BRANCHES.md)、[V15 结论](../experiments/015_controlled_comparison/amendment_1/ASSESSMENT.md)。

这些结果支持一个待验证假设：模型在“没有证明为真 / 没有证明为假”的边界上有系统性偏差。数据监督可以直接优化这个边界；继续增加提示规则只是已有的一种处理方式。

## 数据足够做先导实验，但不足以保证泛化

本次直接统计开发集：

| 数据 | 样本 | 完整组 | SUPPORTS | REFUTES | NEI | 输入词数中位数 / 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| basic/dev | 720 | 84 | 195 | 246 | 279 | 23 / 51 |
| challenge/dev | 702 | 114 | 271 | 95 | 336 | 153 / 453 |
| 合计 | 1,422 | 198 | 466 | 341 | 615 | — |

词数按 evidence 与 claim 拼接后空白分词统计，不是模型 token 数。

- 198 组中有 193 组包含多个标签，适合学习相近表达对应不同结论。有效独立场景数远少于 1,422，不应把同组变体当作独立证据。
- 挑战集 REFUTES 只有 95 条。AMBIGREF / TEMPSCOPE 没有 REFUTES，LOOKALIKE 只有 2 条、UNIQUE 只有 3 条。模型可能从题型风格猜标签；不能只看总体准确率或 NEI 召回。
- 基础集 720 条审核状态仍是 `pending`；挑战集 702 条为 `adjudicated`。训练前应复核基础集语义与标签，保留原文件，修订另存并记录原因。
- 每个开发组对应独立的 `source_title`；本次未发现开发集内部跨组的完全相同 claim 或 evidence。这不排除模板近重复。
- 挑战证据明显长于基础题，不能不检查 token 长度就统一截到 512。编码器路线需要先审计截断覆盖率，再冻结适合的上下文或分块方案，避免丢掉决定标签的句子。

训练 / 验证只从已有开发数据中划分，例如按机制分层、按完整组约 80% / 20% 划分；所有衍生改写跟随原组，近重复模板需额外排查。验证集用于选超参，不回流训练，最终重训方案另行冻结。两集合可共同参与训练，但评测继续分开报告。

**测试数据的历史暴露必须披露。** NLI 分支保留测试集未用于选法；PJ 分支的全量优化包含这些样本。对新的微调模型，可以继续保持它们未参与梯度更新和调参，但不能声称三条路线在这批数据上都是从未接触过的盲测。三路线最终比较应另建独立出题、独立标注的新评测集，覆盖三标签、七类挑战机制、基础能力及自然长文本。V15 已知错例只适合作开发回归集。

## 不使用特殊提示词，具体如何训练

### 主线：只监督标签的 LoRA

固定输入示例：

```text
Classify the claim using only the evidence.
Return SUPPORTS, REFUTES, or NOT ENOUGH INFO.

Evidence: {evidence}
Claim: {claim}
```

训练目标只有正确标签及结束符。输入部分不计入监督损失，模型自身所需的聊天模板保持固定，关闭 thinking。没有题型解释、规则清单、few-shot、金标理由或根据 mechanism 选择的提示词；仅替换两段输入文本。`id`、`group`、`mechanism` 等用于分组和统计，不进入模型。

使用标准交叉熵训练 LoRA 参数，冻结主干；先验证简单监督是否有效。正式实验可从 rank=16、alpha=32、dropout=0.05、学习率 `1e-4`、有效 batch=16、最多 3 个 epoch 开始，以固定验证集选 checkpoint，并报告 3 个随机种子。这些是拟议起点，尚未调参；模块名、序列长度、精度和 batch 需经过实际模型的前向 / 反向小样本检查。

第一版同时使用基础和挑战训练数据，防止只纠正 NEI 而损伤原有判断能力。先保留自然标签分布、平衡两数据来源，不直接大幅放大 NEI 权重。推理只返回标签；非法输出仍计错，不能用金标或题型规则修正。

备选模型 [Qwen3-8B 官方模型卡](https://huggingface.co/Qwen/Qwen3-8B) 报告 8.2B 参数，并支持关闭 thinking。这里选的是可训练原始权重，不是当前服务的 27B W8A8 文件。LoRA 与量化适配的能力范围应按 [PEFT 官方说明](https://huggingface.co/docs/peft/developer_guides/quantization) 及实际后端验证。

### 严格无提示词的对照：文本对分类器

```text
(evidence, claim) → 编码器 → 三分类头 → 三个类别概率 → argmax
```

可使用 `microsoft/deberta-v3-base`，按文本对编码后训练分类头及主干。其 [官方模型卡](https://huggingface.co/microsoft/deberta-v3-base) 报告 86M 主干参数和 98M 嵌入参数，总计约 184M，远低于课题上限。无需自然语言指令，也无需生成理由。

这条路线更直接、模型较小，适合做训练基线，但能否保留长证据推理能力需要实测。可比较“冻结编码器、只训练分类头”与“连同编码器微调”；不能把随机初始化的未训练分类头当作有意义的微调前性能。

### 可选增强：对比样本，而不是更多规则

先利用现有训练组中标签不同的变体；若基础 SFT 仍不足，再增加经过审核的最小对比样本，例如：

| evidence | 相同 claim：Riley received the grant. | 标签 |
| --- | --- | --- |
| Riley denied receiving the grant. | 只报告否认行为 | NEI |
| Riley did not receive the grant. | 直接否定事件 | REFUTES |
| Riley received the grant. | 直接肯定事件 | SUPPORTS |

上表只是方法说明，不是已纳入训练的样本。应更换人物、句式、文体和上下文，避免仅换名字来制造虚假的样本量；全部变体只能留在训练侧。基础题需要同步保留。不要直接把现有 NLI / PJ 的输出当正确标签，以免复制其共同错误。

外部候选可考虑经去重和标签口径核验的 NLI / VitaminC 训练数据。[VitaminC 原论文](https://aclanthology.org/2021.naacl-main.52/) 研究的正是相似证据对应不同事实判断的训练设计；论文结果不能直接推算为本仓库的提升。外部数据仅作为后续独立实验臂，记录来源、版本、许可与重复检查；不能把“检索不到证据”的数据随意当成本任务“给定证据不足”的监督。

[LlamaFactory 官方文档](https://github.com/hiyouga/LlamaFactory/blob/main/README.md#for-ascend-npu-users) 提供昇腾安装路径；[昇腾 bitsandbytes 文档](https://ascend.github.io/docs/sources/bitsandbytes/index.html) 也有 NPU 示例，所以不应笼统声称昇腾不能 QLoRA。当前包和现有量化格式的适配仍需单独验证，本轮建议先用 BF16 LoRA 减少量化后端这一变量。

## 怎样判断微调真正有效

建议最小实验矩阵如下，所有评测使用相同样本和固定标签口径：

| 实验臂 | 回答的问题 |
| --- | --- |
| 8B 原模型 + 固定简短输入 | 同模型微调前基线 |
| 同一 8B + LoRA，输入完全相同 | 参数训练是否带来收益 |
| 同一 LoRA + 训练侧对比样本（可选） | 数据增强是否额外有效 |
| 27B + 冻结 NLI / PJ v3 | 是否有实际替代现有方案的价值；不是纯训练因果比较 |
| 文本对分类器（对照） | 完全没有提示词时能达到什么水平 |

分别报告 basic / challenge 准确率、Macro-F1、三类召回、各机制表现、NEI→REFUTES 错误率、S/R→NEI 退化、非法输出和推理耗时。原指标实现可参考 [metrics.py](../src/ab_factcheck/metrics.py)，适配时保持失败样本分母一致。

选型只能使用开发验证数据；最好再检查留出模板或留出机制上的退化，注明其样本规模限制。正式比较按 group / 模板族进行配对统计，不能把相关变体当独立样本，也不能把多个训练种子当成多份测试数据。

候选推进标准可以沿用仓库关注的方向：挑战准确率有实质提升（例如至少 5 个百分点），同时基础准确率下降不超过 2 个百分点、各类召回下降不超过 5 个百分点。具体主指标、比较对象、样本量和检验方案应在新评测前冻结；这些幅度阈值本身不是统计非劣效证明，不能事后为了通过而修改。

**下一步是实现和验证一个小规模标签监督训练闭环，不是直接训练当前在服 27B。** 顺序为：审核与冻结数据 → 建立独立训练环境和原始权重 → 小样本反向检查 → 同模型微调前后开发比较 → 达到预定条件后进行新的独立评测。
