# 第二轮实际结果与研究结论

2026-10-22 完成最终运行 `pilot_qwen3_4b_q4_struct_v2_r2`。本轮消除了正式样本的 JSON/字段失败和生成截断，但没有得到双世界方法全面优于直接分类的结果：B2 在挑战集取得有限净收益，在基础集明显退步；单个 NEI 示例使两套数据的总体准确率进一步下降。

## 实际执行与必要修复

复用同一份 Qwen3-4B-Instruct-2507 Q4_K_M、llama.cpp b11669、原有 87/60 条 pilot 及其顺序。三组统一 temperature=0、seed=42、context=8192、max_tokens=1024，每个理由最多 320 字符，单槽串行。实际 GPU offload 为 37/37 层。没有下载或替换模型，没有使用封存测试集。

执行过程中遇到的问题均保留证据：

1. 最初按后端文档把 schema 放在 response_format 外层。3 条真实探针证明它只保证任意 JSON，不保证指定字段。检查固定版本源码后改为 `response_format.json_schema.schema`。
2. 未限制理由长度的 r1 通过 9 条 smoke，但正式第 165 条的 B2 理由循环自我修正，耗尽 1024 tokens。立即停止，保留 165 条真实记录及 276 条未运行状态。
3. 最终 r2 为三个条件的理由统一增加简单 `maxLength: 320`。实测有/无长度约束分别输出 16/100 个字符，确认后端支持。使用全新 ID 重新运行全部 A2/B2/C2，不混用或覆盖 r1 的结果，也不对单题重生成到答对。

最终 r2 完成 **441 条正式请求、9 条 smoke、5 条约束验证请求**；每条正式请求均只尝试一次。连同此前明确保留的失败探针和部分运行，本次专用服务日志共 635 次生成，独立审计已核对。

## 约束生成解决了什么

- 441/441 条正式输出为严格合法 JSON，字段、枚举、理由长度均符合 Schema，协议有效率为 **100%**。
- 生成截断 **0 条**；最大实际输出 231 tokens，最大输入 1,019 tokens，预检与后端 token 计数一致。
- **7 条双 IMPOSSIBLE** 属于逻辑组合无效，按错误计分：挑战集 C2 两条、基础集 B2 两条及 C2 三条。它们不是格式故障。
- **48 条理由触及 320 字符上限**：挑战集 B2/C2 为 18/10 条，基础集为 13/7 条。解释可能被约束提前结束，已独立标记，不能把“JSON 完整”解释成“理由完整且正确”。

因此，本轮整体输出方案解决了此前的大量格式失败，但未单独隔离 Schema、预算和理由长度约束各自的因果贡献。结构化生成不是逻辑正确性的保证。

| 数据集 / 召回 | A2 | B2 | C2 |

| 挑战集 NEI | 22.50% | 70.00% | 65.00% |
| 挑战集 SUPPORTS | 87.88% | 63.64% | 21.21% |
| 挑战集 REFUTES | 85.71% | 42.86% | 64.29% |
| 基础集 NEI | 43.48% | 91.30% | 78.26% |
| 基础集 SUPPORTS | 92.86% | 64.29% | 14.29% |
| 基础集 REFUTES | 82.61% | 17.39% | 52.17% |

A2 把 NEI 错判为 REFUTES 的样本中，B2 在挑战集纠正 17/27 条、基础集纠正 7/8 条；C2 对应为 13/27 和 6/8 条。

与此同时，B2 将 A2 原本正确的 SUPPORTS 改成 NEI：挑战集 10 条、基础集 4 条；将原本正确的 REFUTES 改成 NEI：挑战集 3 条、基础集 13 条。C2 相对 A2 的正确 SUPPORTS→NEI 误伤更大，分别为 23 条和 11 条。

分机制观察：DENIAL 的 B2 准确率从 A2 的 43.75% 升至 75%，但只有 16 条、2 组。SETCLOSE、UNIQUE 的 B2 NEI 召回仍仅为 33.33%、28.57%。TEMPSCOPE 的 A2/B2 总准确率同为 80%，实际上 NEI 正确数从 4 增至 6，而 SUPPORTS 正确数从 4 降至 2，收益与损失抵消。不能仅凭 NEI 召回认定整体推理能力提升。

## 已可排除格式因素的逻辑问题

以下两个正式样本均为完整 JSON、正常结束，理由没有触及字符上限。分析只依据给定 Evidence，不引入外部人物事实，不修改原始标签或预测。

- **B2 / basic / `e_5c7b1b9b012be799`（FUNCTIONAL）**：证据说某人曾住在 Portland 和 Salem，Claim 仅说他曾住在 Salem。模型把两个世界都标为 POSSIBLE，产生 NEI；其 false_reason 同时承认 Claim 为假会与证据矛盾。这里既有错误的世界状态，也有状态与理由不一致，程序映射标签无法修正错误的状态字段。
- **C2 / challenge / `e_83ecbf82546d00f0`（TEMPSCOPE）**：证据断言 Jamie Vardy 在 2023–2027 年任队长，Claim 问 2026 年是否任队长。模型构造“2023–2027 年任队长，但 2026 年例外”的假世界，并标为 POSSIBLE。这一例外改动了证据已经给定的任职区间，不符合保持 Evidence 为真的要求。

另有合成 smoke 中的清晰反例：B2 面对“恰好三个红方块”的证据和“恰好四个红方块”的 Claim，将 true_world 填为 POSSIBLE，尽管理由承认数量矛盾。该例不计入正式性能，只用于说明状态判断与理由的一致性仍未解决。

按照冻结标签，格式与逻辑组合均有效但分类错误的记录为：挑战集 A2/B2/C2 分别 37/32/43 条，基础集为 18/24/25 条。完整错误和世界状态复核清单已生成；除上述可直接核对的例子外，不自动把全部错误归入某一语义原因，基础集原有 pending 审核标记也保留。
