## 三个新方向

- `compatibility`：分别判断 E 与 C、E 与整句 C 的否定是否相容，分别给一句见证或冲突说明。Python 将真/假可能性映射为三分类；两者都不可能时记 INVALID。这里只是模型估计，不是 SAT 证明，也不把某个坏见证当作全体不可满足。
- `normalize`：在同一次调用中先做简短保义复述，再判断原文之间的 NLI 关系。复述不得加强或削弱原意；原始文本始终在上下文内。该方法可能引入复述误差，按实际准确率计分，不假设复述一定有用。
- `contrast`：对 ENTAILMENT、CONTRADICTION、NEUTRAL 分别给一句核验，再选择关系。三个候选均接受检验，没有标签专属阈值。

每个新方向还离线计算一个对称融合：新方向与 V9 一致时使用其答案，否则回退 A27。单方案部署一次调用；融合需要 A27、V9、新方向三次调用。模型保持 `reasoning_effort=none`，简短结构化核验不等于打开模型思考模式。

## 节约 token 的冻结流程

1. 从原 42 道探索开发题中选 14 题，每套数据每种机制一题，三类标签计数为 2/2/3。固定 hash 在满足分层约束的子集中选择，不使用模型预测或正确率。开发标签只在本地用于抽样和评分。
2. 三个方向各调用 14 题，共 42 次。历史 A27/V9 对照复用已核验缓存。
3. 仅一个底层方向晋级，补齐 42 题，共增加 28 次。
4. 在直接使用和融合中选一个候选。只有相对 V9 总正确数严格增加、且任一数据集最多少对一题时，才继续确认；否则停止，记录负结果，不使用新确认题。
5. 条件确认清单已在任何 V10 调用之前冻结：28 题，来自 14 个此前未使用组，每组两题。排除历次 pilot、V5、V7、V8、V9 的组。确认同时新跑 A27、V9 和新方向，共 84 次；不从确认结果重新挑选方法。

最多新增 154 次响应；若未通过扩展门槛，则只用 70 次。确认是新组的小切片，不是完整组、全开发集或测试集。晋级规则是工程筛选，不是统计显著性判据。

历史缓存与当前调用的时间不同，托管后端及生成波动可能影响探索分数；因此通过筛选后会在新题上同期重跑两个对照。未进入确认的负结果只适用于本轮筛选，不等于证明该方法在所有任务上无效。

`plan.json`、`freeze.json` 保存清单、协议、源码及输入哈希；`shortlist.json`、`winner.json` 保存晋级决定及前一阶段指标哈希。模型成功响应不重新生成。所有文件在本仓库内。
