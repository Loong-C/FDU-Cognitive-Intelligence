# 冻结统一评估的结论

评估于2026-10-30完成。NLI与PJ v3均使用冻结的统一协议，在336道新构造受控题上完成672个评分单元；原始响应、逐题预测、指标与精确置换检验已独立复算。完整代码测试250项通过。

**PJ v3在这批挑战题上多对8题，基础题持平，但没有通过事前的优越性主标准。** 不能将这一结果写成“已经证明v3优于NLI”，也不能将两者的基础满分解释为自然文本基础能力已获保证。

| 指标 | NLI | PJ v3 |
|---|---:|---:|
| 基础准确率 | 168/168（100%） | 168/168（100%） |
| 挑战准确率 | 148/168（88.10%） | 156/168（92.86%） |
| 挑战Macro-F1 | 0.8770 | 0.9277 |
| 挑战NEI召回 | 36/56（64.29%） | 44/56（78.57%） |
| 挑战SUPPORTS/REFUTES召回 | 均100% | 均100% |
| 无效输出 | 0 | 0 |
| 评分对应实际token | 110,596 | 351,171 |

PJ v3挑战准确率增加4.76个百分点，未达到预设至少5个百分点（本样本规模至少需净增加9题）；双侧模板族置换p=0.25，也未达到alpha=0.05。基础点估计限制通过，但这不是统计非劣效证明。

## 改善来自哪里

- 否认类DENIAL：17/24 → 24/24，净多对7题。
- 指代类AMBIGREF：23/24 → 24/24，净多对1题。
- 其余五类机制的正确数相同。LOOKALIKE中各自有2道独有正确题，净持平不等于逐题答案相同。
- 两种方法的全部错误都发生在NEI：NLI有20题、v3有12题。相对NLI，v3纠正10题、损害2题。
- SETCLOSE的8道NEI两者全错；共同错误还包括PRESUP的2道NEI。细化规则仍未可靠处理“名单仅封闭某个子集”的情况。

例：证据只说两项软件项目获奖，不能据此排除另一项非软件项目获奖；证据只列某个出生时间段的两个孩子，不能排除其他时间出生的孩子。现有两种方法在这些受控题上仍错误地选择REFUTES。

## 为什么不能把8题增益当成已验证优势

每套168题仅来自14个手写模板族，四个人名/数值变体不是四个独立模板。净增益集中在3个模板族（DENIAL两族、AMBIGREF一族），按预定模板族检验不足以排除随机符号变化。不得改用逐题独立假设来追求显著结果。

`metrics.json`另保存了按机制内重抽模板的描述性bootstrap区间（+3.57至+5.95个百分点）。每机制仅两个模板，且固定保留机制构成，使每次重抽都保留DENIAL的正增益；这个窄区间不是主检验的替代品，也不证明自然文本总体优势。主结论仍以预定p=0.25和5个百分点门槛为准。

基础题全部正确呈现明显的满分情况，这套题未能进一步区分两种方法的基础能力；不能据此断言更难、更长或真实文本上不会退步。

## 成本和可追溯性

相同输出上限不意味着相同消耗。PJ v3输入提示词更长，评分对应token为NLI的3.175倍；两者输出token分别为23,164和23,835，主要成本差异来自输入。这里比较token，不将其直接换算为实际付费或耗时倍数。

最终评分使用282条无条件复用响应和390条新增响应。因评分前语义修订而归档、不参与最终评分的旧响应54条；能力预检共6条。因此可见响应总计732条、502,691 tokens。原轮中断时另有4个请求未收到响应，用量未知，不计为零。732条可见响应的服务fingerprint均为`vllm-0.30.0-tp4-04d31769`；这是服务自报信息，不等于独立验证模型权重哈希。

修订原因、范围与复用规则见[修订说明](README.md)和[机器可读记录](amendment.json)。在查看模型答案和分数前，修正48道题的单次事件/唯一性范围限定；方法、标签、分组和统计规则保持不变。原冻结与旧响应均保留，不能把过程写成从未修订的完整盲测。

## 可支持的结论

这次工作已经完成方法冻结、协议统一、两套受控评估及独立复算。v3在当前挑战题上观察到收益，同时token消耗更高；现有证据不足以宣布它在独立自然文本上更优。NLI可继续作为成本较低的参照，v3保留为规则增强候选。

数据由了解双方方法的同一助手构造，题目短、标签均衡、模板有限。标签经过真值枚举与Z3复核，但自然语言与形式模型的对应未经独立人工裁决。后续若用本轮错误修改方法，本题集只能作为开发回归集；泛化结论需要新的独立出题与自然文本评估。
